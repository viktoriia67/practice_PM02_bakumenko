# Система бронирования отелей

## Описание проекта

Проект реализует сервисный слой системы бронирования отелей с использованием архитектурных паттернов Repository, Service Layer, Dependency Injection и Unit of Work.

Система позволяет:

* хранить информацию об отелях;
* хранить информацию о номерах;
* создавать бронирования;
* отменять бронирования;
* рассчитывать штраф при отмене;
* искать свободные номера на заданные даты;
* учитывать погодные условия через внешний сервис погоды.

## Архитектура

### Domain Layer

Содержит бизнес-сущности:

* Hotel
* Room
* Booking

Также содержит доменные исключения:

* DomainError

### Repository Layer

Для доступа к данным используются репозитории:

* HotelRepository
* RoomRepository
* BookingRepository

В тестах используются InMemory-реализации репозиториев.

### Service Layer

Основная бизнес-логика сосредоточена в классе BookingService.

Реализованы операции:

* create_booking()
* cancel_booking()
* find_free_rooms()

### Unit of Work

Для координации работы репозиториев используется паттерн Unit of Work.

Интерфейс:

* AbstractUnitOfWork

Тестовая реализация:

* InMemoryUnitOfWork

### Dependency Injection

Все зависимости передаются через конструктор сервиса:

```python
uow = InMemoryUnitOfWork()
service = BookingService(uow)
```

Это уменьшает связанность компонентов и упрощает тестирование.

## Бизнес-правила

### Создание бронирования

Перед созданием бронирования выполняются проверки:

* номер существует;
* дата начала меньше даты окончания.

После успешной проверки создаётся бронирование со статусом CONFIRMED.

### Отмена бронирования

Перед отменой выполняются проверки:

* бронирование существует;
* бронирование имеет статус CONFIRMED.

Если на дату заезда ожидается шторм, штраф не взимается.

В остальных случаях штраф рассчитывается в зависимости от даты отмены.

После отмены статус изменяется на CANCELLED.

### Поиск свободных номеров

Система проверяет все номера отеля и возвращает только те, для которых отсутствуют активные бронирования на выбранный период.

## Тестирование

Для тестирования используется:

* pytest
* unittest.mock

Проверяются следующие сценарии:

* создание бронирования;
* отмена бронирования;
* поиск свободных номеров;
* обработка ошибок;
* работа Unit of Work.

Запуск тестов:

```bash
pytest -v
```
